# ccusage-pricing-snapshots

The pricing snapshots the binary embeds, and nothing else: three byte
constants that `ccusage-core` inflates once the binary hands them over through
`ccusage_core::pricing::set_embedded_snapshots`.

## Owns

- `build.rs` — compacts the pinned LiteLLM snapshot and minifies and deflates
  every snapshot into `OUT_DIR`. It reads `CCUSAGE_PRICING_JSON_PATH`, which
  every Nix build and the dev shell set; the `fetch-litellm-pricing` feature adds
  the HTTPS download that plain `cargo build` needs on platforms Nix cannot
  target. The committed files stay indented for reviewable regeneration diffs,
  and at 2K+ models the models.dev JSON alone would otherwise add a quarter
  megabyte to the binary.
- `src/models-dev-pricing.json` and `src/models-dev-catalog-rules.json` — the
  committed models.dev snapshots, regenerated by `just gen-models-dev-pricing`.
- `src/lib.rs` — `LITELLM_PRICING`, `MODELS_DEV_PRICING`, and
  `MODELS_DEV_CATALOG_RULES`.

The snapshots used to live in `ccusage-core`, where every scheduled snapshot
refresh recompiled that crate and every adapter built on it. Here only the
binary depends on them; tests reach them through `ccusage-core`'s
`test-snapshots` feature, enabled from `[dev-dependencies]`.

## Depends on

Nothing at runtime. `miniz_oxide`, `serde_json`, and the optional `minreq` are
build-dependencies.

## Build layer

Outside the Crane artifact layers: it is compiled with the final binary, so a
snapshot refresh leaves the cached layers untouched. Verified by comparing the
foundation and adapters layer derivation paths before and after editing
`src/models-dev-pricing.json` and overriding the `litellm` flake input.
